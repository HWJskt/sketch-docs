# 공통 편집기 헤더와 프로그램 정보 화면 계획

기준일: 2026-10-11. 두 편집기의 실행 화면을 1440×1000 Chrome에서 비교하고, 사용자가 제공한 EdenText 0.9.0 정보 창 이미지를 참고했다. 파일 메뉴 hover 및 공통 헤더·전환·정보 창을 구현했다. 2026-10-12 검증 결과는 [구현 검증 기록](../validation/2026-10-12-common-shell.md)을 따른다. 아래는 구현의 설계 기준이다.

## 현재 화면과 메뉴 수정

Word는 상단에 파일·리본 탭·검색·문서명·설정과 로고가 있고, 아래에 리본 도구가 배치된다. 한글은 메뉴, 편집 아이콘, 글꼴·서식의 세 줄로 구성된다. 두 화면 모두 도구 영역 아래에서 문서가 시작하지만 문서명·정보 버튼의 위치와 엔진 식별 표시가 일치하지 않는다.

한글 원본 메뉴는 처음 클릭으로 연 뒤 다른 메뉴 제목으로 마우스를 이동하면 전환된다. 닫힌 상태에서 hover만으로 여는 방식은 아니다. 우리 파일 메뉴도 같은 전환에 참여하도록 수정했다. 편집→파일→입력→파일을 클릭 없이 이동하며, 파일의 항목으로 내려가도 메뉴를 유지한다. Escape·바깥 클릭·메뉴 실행과 관련 이벤트 정리는 유지한다.

## 공통 헤더 배치

**2026-10-12 사용자 변경 결정:** 아래 최초 설계의 독립 40px 행은 제거했다. 현재는 각 엔진의 기존 첫 메뉴 행 오른쪽에 `W / 한 / ⓘ`를 넣어 문서 영역 높이를 회복한다. 메뉴 영역과 버튼 영역의 너비를 나누고 좁은 화면에서는 메뉴만 스크롤한다. 아래 40px 배치 설명은 최초 설계 이력이다.

두 엔진 위에 우리 코드가 소유하는 높이 40px의 공통 헤더를 추가한다. 엔진 내부의 서로 다른 위치에 전환 버튼을 각각 삽입하는 방식보다 위치를 안정적으로 유지하고 upstream 패치 범위를 줄일 수 있다.

```text
Word 선택: [문서 아이콘 W  Word ●] [문서 아이콘 한  한글]       [프로그램 정보 ⓘ]
한글 선택: [문서 아이콘 W  Word]   [문서 아이콘 한  한글 ●]     [프로그램 정보 ⓘ]
           ─── 아래에는 선택된 편집기의 기존 메뉴와 도구 ───
```

- 왼쪽 동일 좌표에 아이콘과 텍스트를 함께 표시한 두 개의 전환 버튼을 둔다. 활성 배경·테두리·선택 상태로 현재 편집기를 구분하고 `aria-pressed`를 제공한다. 색상만으로 구분하지 않는다.
- Word는 DOCX/ODT, 한글은 HWP/HWPX용 편집기임을 툴팁 또는 접근 가능한 설명으로 안내한다. 현재 문서 확장자와 현재 엔진은 별개의 정보다.
- 오른쪽에는 접근 가능한 이름이 있는 프로그램 정보 아이콘을 둔다. 좁은 화면에서도 엔진 선택 텍스트는 유지한다.
- 엔진의 파일 메뉴와 문서 편집 기능은 유지한다. 상단 전환은 문서 형식 변환 기능이 아니다.
- 새 공통 헤더 아래의 편집 영역은 남은 높이를 채우도록 한다. 현재 iframe와 한글 컨테이너의 `100dvh`를 그대로 두면 40px만큼 넘치므로 부모 높이에 맞추도록 수정한다.
- Word 리본과 한글 도구를 완전히 같은 모양으로 재작성하지 않는다. 공통 헤더의 높이·배경·구분선·버튼 규격만 통일한다.

## 전환 시 문서 보존

단순히 다른 HTML로 이동하면 한글의 메모리상 미저장 문서가 사라질 수 있다. 공통 셸이 두 엔진의 세션을 소유하고 처음 선택할 때만 로드하는 구성을 우선 구현한다.

1. 엔진을 한 번 로드하면 편집기 전환 시 제거하지 않고 숨긴다. 되돌아오면 본문·표·선택·파일 연결·실행 취소 이력이 유지되어야 한다.
2. 숨긴 엔진은 `inert` 처리하고 포커스를 해제한다. 단축키·편집 입력이 숨긴 엔진에 전달되지 않는지 확인한다. 엔진이 지원하는 경우 불필요한 렌더링을 일시 중지한다.
3. 각 엔진의 dirty·busy·문서명·저장 대상을 분리한다. 저장 중 전환은 막고, 단순 전환에서는 내용을 버리지 않으므로 저장/폐기 확인을 요구하지 않는다.
4. 탭 닫기·새로고침·세션 교체에는 두 엔진 중 하나라도 미저장 상태면 경고한다. 비활성 엔진까지 포함하는 공통 상태 계약이 필요하다.
5. 주소로 직접 접속하면 해당 엔진을 선택한다. 앱 안에서는 페이지를 새로 로드하지 않고 활성 엔진과 URL을 동기화한다. 뒤로/앞으로 이동도 같은 전환 규칙을 적용한다.
6. 두 엔진 로드 후 메모리 사용을 실측한다. 자동으로 숨긴 엔진을 제거해 문서를 잃는 최적화는 하지 않는다. 새로고침 후 한글 복구는 별도 미구현 기능이며 전환 시 보존과 혼동하지 않는다.

Word 안의 기존 '한글 문서 열기 / 새 문서' 경로와 네이티브 오버레이도 공통 셸과 연결해 헤더 표시가 실제 엔진과 달라지지 않도록 해야 한다. iframe 내부 DOM만 보고 dirty 상태를 추정하지 않고 최소한의 상태 브리지를 둔다.

## 프로그램 정보와 소스 제공

사용자 이미지처럼 중앙 모달 카드에 로고·프로그램명·소개·버전·링크를 배치한다. 우리 제품 버전은 루트 package 기준으로 표시하고 EdenText 버전과 혼동하지 않는다. 제품명은 사용자 결정으로 Sketch Docs이며 간단한 문서 기호를 사용한다. 저작권자 명칭은 아직 지정하지 않았으며, 병원 도메인만으로 법적 저작권자 명칭을 만들어 넣지 않는다.

진입점은 다음 두 곳이다.

- 에디터 선택 화면(`/`) 하단: **프로그램 정보 · 라이선스 및 소스 코드**.
- Word와 한글의 공통 헤더 오른쪽: **프로그램 정보** 아이콘. 직접 URL로 들어와도 안내에 접근할 수 있다.

정보 창에 표시할 내용:

1. 우리 프로그램명·버전·간단한 소개, 수정 사실과 배포 날짜.
2. 우리 배포판의 AGPL-3.0-only 표시와 원문 링크. 현재 루트 LICENSE를 기준으로 하며 개별 구성요소의 별도 라이선스를 유지한다.
3. **이 버전의 소스 다운로드** 버튼. 배포판과 일치하는 우리 코드·원본·빌드 자료의 대응 소스 묶음에 연결한다. 원격 저장소를 정하면 GitHub 링크도 추가하되 다운로드를 대체하는 장식 링크로 취급하지 않는다.
4. **오픈소스 및 타사 라이선스**: EdenText AGPL, HOP/rhwp MIT, 의존성·폰트 고지와 각 저작권자. 원본의 고지·면책을 보존한다.
5. 보증 부인과 라이선스에 따른 재배포 가능 안내. 원본 이미지의 '개인정보 보호' 문구는 AI 전송·브라우저 복구 등의 실제 동작과 검토 없이 그대로 복사하지 않는다.

AGPL은 눈에 띄는 법적 고지 및 적용되는 대응 소스 제공을 요구한다. 선택 화면에 진입점을 두되 실제 이용 화면에서도 접근 가능하게 하고, 배포 전 링크가 실제로 해당 소스를 내려주는지 검증한다. 모달·링크만 만들고 소스 묶음을 제공하지 않는 상태는 배포 완료가 아니다. [AGPL §0·5·6·13](https://opensource.org/license/agpl-3.0)

공통 정보 창은 EdenText를 우리 앱으로 위장하거나 원저작권 표시를 지우기 위한 것이 아니다. 기존 EdenText 정보 창과 고지는 보존하고, 우리 앱과 구성요소를 구분해 안내한다. 라이선스·폰트 관련 남은 검토는 [라이선스 기록](../validation/2026-10-11-licenses.md)을 따른다.

## 구현 순서와 검증 기준

1. 공통 셸과 40px 헤더, 동일 아이콘 버튼, 각 엔진 높이 조정.
2. 두 세션 유지와 상태 브리지, 전환·포커스·미저장 보호 연결.
3. 공통 정보 창, 선택 화면 링크, 고지와 대응 소스 패키징 연결.
4. Word에 본문·표 작성→한글에 본문·표 작성→각 엔진으로 복귀→각각 저장·재열기 검증. 저장 대상·변경 상태가 섞이지 않아야 한다.
5. 헤더 위치·선택 상태·키보드 접근·좁은 화면·메뉴 겹침, 로딩 실패 후 기존 문서 유지, 두 엔진 동시 유지의 메모리 사용 확인.
6. 정보 창의 Escape·포커스 복귀, 양쪽 편집기와 첫 화면의 동일 정보, 소스 다운로드와 배포판 버전 일치, 고지 링크 접근 검증.

공통 헤더·정보 창과 소스 패키징을 구현하고 프로덕션 `npm run verify`를 통과했다. OS 선택기·실제 오피스 호환·IME·모바일 Safari는 별도 수동 검증 대상으로 남는다.
