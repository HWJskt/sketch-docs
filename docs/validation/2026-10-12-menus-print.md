# 상단 메뉴 정리와 한글 인쇄

2026-10-12 사용자 요청에 따라 상단 중복 버튼을 정리하고 파일명 표시와 한글 인쇄를 연결했다. 원본 클론은 수정하지 않으며 빌드 오버레이와 제품 셸에 적용한다.

## EdenText 고지 검토

현재 고정 커밋의 LICENSE는 AGPL-3.0이다. §0은 접근하기 쉽고 눈에 띄는 저작권·보증 부인·라이선스 열람 안내를 정의하고, §5(d)는 해당 법적 고지를 수정 UI에서도 요구한다. §6(d)·§13의 대응 소스 제공도 유지한다. 특정 로고 버튼·아이콘·좌표를 유지하라는 조항은 확인되지 않았다. 따라서 로고를 없애는 대신 상시 접근 가능한 공통 ⓘ에서 필요한 고지와 원래 EdenText 정보 창으로의 연결을 제공하는 방식으로 통합했다. 이는 확인한 라이선스 문구에 대한 구현 판단이며 별도의 법률 인증은 아니다.

- 공통 정보 창에서 `EdenText · Copyright © 2026 Steffen Becker`를 펼침 없이 표시한다. 저작권자 표기는 고정 버전 README의 원문을 사용했다.
- 원본 저장소 링크, AGPL 원문, 타사 고지, 해당 빌드 소스 다운로드, 수정 및 보증 부인 안내를 유지한다.
- Word에서 ⓘ → EdenText 정보로 원래 정보 창을 열 수 있다.
- Word 엔진 직접 URL처럼 공통 셸이 없는 환경에서는 원래 로고 버튼을 숨기지 않는다.

근거: [고정 버전 LICENSE](https://github.com/stffnb/edentext/blob/4c4c94cb46b9c0b1473b9dd323315f9c4d365251/LICENSE), [고정 버전 README](https://github.com/stffnb/edentext/blob/4c4c94cb46b9c0b1473b9dd323315f9c4d365251/README.md). 라이선스 문서 첫머리 FSF의 저작권은 라이선스 문서 자체의 저작권이므로 EdenText 저작권자로 표시하지 않는다.

## 구현

- Word 상단 로고·언어·화면 표시 아이콘 숨김. 설정 안의 언어·테마 선택은 유지한다. 기본값은 한국어이며 설정에서 사용자가 명시한 언어 선택은 존중한다.
- Word 명령 검색 placeholder를 `메뉴검색`으로 변경한다.
- Word 문서명 입력을 텍스트로 교체하고 확장자를 유지한다. 열기·저장·다른 이름으로 저장 후 실제 파일명을 표시하고 취소·쓰기 실패는 이름을 바꾸지 않는다.
- 한글 메뉴 행 오른쪽에도 현재 파일명을 표시한다. 새 문서는 `새 문서`, 열기/저장 후에는 확장자를 포함한 파일명이다. 긴 이름은 말줄임하고 title로 전체 이름을 제공한다.
- 한글 파일 메뉴의 문서 형식 선택을 제거하고 `인쇄…`를 추가한다.
- 인쇄는 전체 쪽의 print-profile SVG와 실제 용지 크기를 snapshot하여 별도 인쇄 iframe에 넣고 브라우저 print를 호출한다. 편집 도구는 출력하지 않는다. dirty·revision과 저장 대상을 변경하지 않고 인쇄 iframe을 정리한다.

## 검증 범위

`volta run --node 24.21.0 npm run verify` 통과. 제품과 생성된 Word 타입 검사 오류·경고 0, 파일/소스 계약 5개와 프로덕션 Chrome 회귀 검사 통과.

Chrome 개발 서버 회귀에서 숨긴 버튼, 메뉴검색, 읽기 전용 파일명, 실제 저장명 갱신, 공통 정보→원래 EdenText 정보, 한글 파일명 갱신을 확인했다. 인쇄의 window.print 호출은 시험에서 가로채어 생성된 SVG를 확인하고 Chrome PDF로 출력했다. A4 1쪽에 한글 본문과 2×2 표가 보이는 것을 확인했으며 인쇄 전후 dirty/revision 동일, 임시 iframe 제거를 검사한다. 실제 OS 인쇄창과 물리 프린터는 별도 수동 확인 대상이다.

## 한글 기능 검색 검토

구현 가능하다. 실제 Chrome에서 현재 embed 명령 목록 178개를 확인했다. `rhwpStudio.automation.listCommands()`는 명령 ID·한국어 label·단축키·현재 enabled·opensDialog를 제공한다. `getMenuModel()`로 메뉴 경로를 얻고 `execute(id, params, {allowDialog:true})`로 기존 dispatcher와 실행 가능 판정을 유지할 수 있다.

권장 구현은 첫 메뉴 행에 작은 `메뉴검색` 상자를 두고 한국어 명령명·메뉴 경로·동의어를 검색하는 것이다. 위/아래·Enter·Escape와 IME 조합 중 Enter 처리를 구분한다. Word와 같은 Alt/Option+Q는 기존 한글 단축키와 충돌 검사를 거쳐 연결한다. 선택 상태를 보존하여 표·문단 명령의 대상이 달라지지 않게 해야 한다.

새 문서·열기·저장·다른 이름으로 저장·인쇄는 embed에서 제외된 upstream file 명령을 직접 실행하지 않고 우리 파일 처리 함수로 연결한다. 서식 명령은 기존 automation으로 실행하며 disabled를 무시하지 않는다. 검색창을 여는 시점과 실행 직전에 활성 상태를 다시 검사한다. upstream 갱신 후 명령 ID·레이블·대화상자 계약을 검사한다.

이번 요청의 기능 검색은 검토까지 수행했다. 검색 UI 자체는 아직 추가하지 않았다.

## 첫 행 정렬·문서 상태·단축키 후속 수정

두 편집기의 첫 행은 36px이다. 공통 W·한·ⓘ 영역은 116px 고정 너비이고 버튼은 26×24px이다. 정보 버튼 오른쪽 공간은 6px에서 10px로 늘렸다. 파일명과 미저장 문구는 이 고정 영역 앞에 배치하여 버튼 좌표를 바꾸지 않는다. 한글의 기본 도구 상자 접기 버튼은 파일명 뒤, 편집기 선택 앞에 표시하며 원래 메뉴 이벤트 연결을 유지한다.

한글 bridge가 파일명 변경, dirty 변경, 문서 교체 이벤트를 구독하여 파일명과 `• 저장하지 않음` 표시를 갱신한다. 문서 세대가 바뀌면 이전 저장 핸들을 해제하여 다른 문서가 이전 대상에 저장되는 것을 막는다. 파일명 변경은 편집기 안의 열기·저장·다른 이름으로 저장에 대한 것으로, 외부 Finder의 파일명 변경을 감시하는 기능은 아니다.

파일 메뉴에 열기 O, 저장 S, 다른 이름으로 저장 HWPX Shift+S, 인쇄 P를 연결했다. Mac에서는 ⌘/⇧, 그 외 플랫폼에서는 Ctrl+/Shift+로 기존 편집 메뉴와 같은 방식으로 표시한다. IME 조합 중 입력·반복 입력·열린 대화상자·진행 중 파일 작업을 구분한다. HWP로 다른 이름 저장에는 별도의 단축키를 부여하지 않았다.

Word 파일 메뉴의 EdenText 정보 항목을 제거하고 공통 ⓘ 경로를 유지했다. 파일 버튼의 배경·글자색·여백을 다른 리본 메뉴와 맞췄다.

검증: Chrome에서 두 편집기의 공통 버튼 3개 전체 좌표·크기 일치, 첫 행 36px, 오른쪽 10px, 파일명/dirty 변경 후 좌표 유지, 한글 접기 버튼 위치와 실제 접기/펴기, 키보드 열기·저장·다른 이름 저장·인쇄, native 열기 후 파일명 갱신을 확인한다. 단축키 계약 시험은 Mac·Windows modifier와 한글 키 입력을 포함한다. Windows 실제 OS 키보드는 수동 확인 대상이다.

창/탭 종료는 브라우저의 `beforeunload` 확인창으로 보호한다. 사용자 지정 ‘저장 / 저장하지 않음 / 취소’ 모달이나 문구는 이 시점에 제공할 수 없다. Chrome 실제 페이지 이동을 취소하여 확인창 발생과 기존 편집 세션 유지를 검사했다. 브라우저의 강제 종료·모바일 프로세스 종료는 이 이벤트를 보장하지 않는다. 앱 안의 새 문서/열기는 별도로 자체 3버튼 모달을 구현할 수 있으나 이번 수정에서는 기존 확인 동작을 유지한다. 근거: [MDN beforeunload](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event).
