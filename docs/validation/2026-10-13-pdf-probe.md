## 소스를 읽고 확인한 동작 (`dist/core/pdf-codec/`)

계획에 영향이 있는 것만 적는다.

- `exportPdf(input, annotations, { mode })`: 기본값 `'incremental'`이다. 암호를 풀어 연 파일이나 머리말 앞에 바이트가 있는 파일은 다시 쓴다(`save({ rewrite: true })`).
- 저장할 때 원본에 더하는 것:
  - 주석마다 annotation 객체와 appearance 스트림
  - 내용(`contents`)이 있는 주석은 Popup 주석 하나를 더 붙임
  - 주석 모델 전체를 JSON 첨부 파일(`EMBEDDED_FILE_NAME`)로 넣음. 그래서 카탈로그의 `/Names`·`/EmbeddedFiles`·`/AF`가 바뀐다.
- 다시 저장하면 자기가 쓴 주석(비공개 키나 첨부 모델의 `/NM`으로 판별)은 지우고 새로 쓴다. foreign 주석은 UI에서 고쳤을 때만 다시 쓴다.
- `saveSupport()`: 암호 파일만 막는다. 서명된 PDF(C1)는 `canSave: true`다. 서명 판별은 우리 코드가 한다(5번 항목처럼 `/V`로).
- 빈 사용자 암호로 열리는 암호 파일은 풀어서 다시 쓴다(보호가 사라짐). 우리 정책은 암호 PDF를 모두 거절하므로 `saveSupport`의 `encrypted` 값으로 막는다.

## 시험을 만들며 알게 된 것

- **Vite worker 형식:** 기본 형식(iife)은 worker의 top-level await를 거부했다(`Top-level await is currently not supported with the 'iife' output format`). 제품 설정에도 `worker: { format: 'es' }`가 필요하다.
- pdf.js 6에서는 `PDFDocumentProxy.destroy()`가 없다. 정리는 loading task의 `destroy()`로 한다.

## 계획에 반영할 것

- 보존 검사의 허용 차이에 다음을 더한다.
  - 새 주석의 Popup
  - 라이브러리의 JSON 첨부 파일과 그 연결(`/Names`·`/EmbeddedFiles`·`/AF`)
  - 이전 저장에서 우리가 쓴 주석의 교체
- foreign 주석을 UI에서 고치면 라이브러리가 다시 쓴다. 기존 주석 보존 원칙과 부딪치므로, foreign 주석은 읽기 전용으로 둔다(라이브러리의 foreign 정책 옵션). 8a에서 정한다.
