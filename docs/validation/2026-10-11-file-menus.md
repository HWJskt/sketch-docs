# 편집기별 파일 메뉴 수정 검증

- Word의 다른 이름으로 저장에서 HWPX/HWP 항목을 제거했다. DOCX/ODT 항목은 유지한다. 기존 변환 구현은 삭제하지 않았지만 더 이상 해당 메뉴로 노출하지 않는다.
- 한글 파일 메뉴를 iframe 안의 편집 메뉴 바로 왼쪽에 배치했다. 원본 메뉴의 CSS를 사용해 한 열의 세로 드롭다운으로 표시한다. 저장 형식 select를 없애고 `다른 이름으로 저장 (.hwpx)`, `다른 이름으로 저장 (.hwp)`로 분리했다.
- 파일 메뉴와 편집 메뉴 간 전환, Escape/외부 클릭 닫기를 확인했다. 새 메뉴는 기존 파일 쓰기·원본 보호·외부 변경 검사 함수를 호출한다.
- `npm run verify` 통과: 루트와 생성된 Word 타입 검사 오류/경고 0, 저장 계약 3건, Chrome 프로덕션 통합 검사. Word 저장 항목, 메뉴 위치·한 열 배치·select 부재, DOCX 저장, HWP/HWPX 본문·표 재열기, 사본 재저장·외부 변경·실패한 열기 유지·오래된 저장 응답 검사 포함.
- `node tests/integration.mjs --dev` 통과. Svelte autofixer 두 컴포넌트 issues 0. 한글 파일 메뉴 스크린샷 직접 확인.
