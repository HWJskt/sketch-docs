# 기본 화면 한국어 메뉴와 한글 저장 연결

기본 앱의 파일 메뉴·저장 형식 선택창에 ODT/DOCX 외에 HWPX/HWP를 추가했다. Word 편집기의 새 문서는 제한된 TipTap→HWPX 변환기를 거쳐 rhwp로 직렬화한다. 동일 파일 재저장과 다른 이름 저장을 지원하며 파일 쓰기 전 외부 변경을 검사한다. 웹 UI 언어의 미설정 기본값은 한국어다. 기존에 명시적으로 선택한 언어는 유지한다.

기본 파일 열기에서 HWP/HWPX를 선택하면 같은 페이지의 한글 편집 화면으로 전환한다. Word 문서로 돌아가면 이전 Word 내용이 유지된다. 두 편집 엔진의 완전한 공통 문서 모델이나 HWP→DOCX 변환이 구현된 것은 아니다.

## 지원 범위

새 Word 문서의 일반 문단, 제목, 기본 글자 서식, 정렬, 단순/병합 표, 용지 크기와 여백을 변환하는 초기 구현이다. 변환기가 보존하지 못하는 노드·서식은 저장을 중단하고 알린다. 머리말/꼬리말, 여러 구역, 워터마크/페이지 장식, 사용자 스타일, 내장 글꼴 등은 명시적으로 거절한다. 가져온 DOCX의 스타일 시트가 기본과 다르면 변환을 거절하므로 임의 DOCX의 완전한 한글 변환을 보장하지 않는다.

한글 파일 쓰기는 데스크톱 Chrome/Edge의 File System Access API를 사용한다. 기존 한글 원본의 덮어쓰기는 이전 단계의 보존 검증 제한을 유지하며 다른 이름으로 저장하도록 한다. 템플릿 샘플 이름과 설명 일부는 영어다.

## 확인 결과

- production build 및 svelte-check: 통과, 타입 오류·경고 0.
- 변환/파일 쓰기 단위 검사: 7개 통과.
- `npm run test:hangul-root`: 실제 Chrome의 기본 화면에서 한국어 파일 메뉴, 한글·영문·굵은 글자 입력, HWPX/HWP 저장, 추가 편집 후 재저장, HWP 다시 열기와 텍스트 확인, Word 문서 유지 검사 통과.
- `npm run test:smoke`: 기존 편집기 입력·자동 저장·ODT 가져오기·PDF 출력·검토 표시 검사 통과. 기존 영어 UI 기반 테스트는 테스트 환경에서만 영어 선택을 명시한다.
- Svelte autofixer 실행: 변경 컴포넌트에 추가한 구문은 정상. 기존 App/Ribbon의 key 없는 each 및 effect 관련 권고는 별도 정리 대상으로 유지했다.

자동 저장 검사는 OS 선택기 대신 실제 OPFS 파일 핸들을 주입했다. 사용자 로컬 디스크의 OS 선택기, 실제 한컴/Word 재열기, IME 조합 입력은 수동 검증이 남아 있다. 라이브 배포는 하지 않았다.

## 개발 서버 한글 엔진 경로 수정

사용자 보고 후 Vite 8.0.14 개발 서버에서 `/rhwp/`가 한글 엔진 대신 기본 EdenText HTML을 반환하는 것을 확인했다. 배포용 preview만으로 수행한 이전 검사는 이 차이를 발견하지 못했다. 변환용 iframe과 한글 편집 화면 iframe 모두 `/rhwp/index.html?chrome=embed`를 명시하도록 수정했다(상대 경로는 유지).

기존 브라우저 저장 검사를 개발 서버에서도 실행하는 `npm run test:hangul-dev`를 추가했다. 수정 전에는 사용자와 동일한 “한글 편집기를 불러오지 못했습니다” 오류로 실패했다. 수정 후 개발 서버에서 HWPX 7,514바이트·HWP 6,656바이트 저장, 재저장, HWP 다시 열기, Word 본문 유지 검사를 통과했다. 사용자의 5173 서버는 종료하거나 재시작하지 않았다.

## 표 크기 변환 보완

`tableRow.rowHeight`를 변환하지 않아 행 높이 조절 후 저장이 거절되는 사용자 보고를 확인했다. CSS px(96dpi) 행 높이를 HWP 단위(7200/inch)로 변환하며, 병합 셀은 병합된 행 높이를 합산한다. 열 너비는 편집기와 동일하게 첫 행의 `colwidth` 비율을 사용하고 병합 셀의 열 너비를 합산한다. 표 외곽 여백·사용자 표 스타일 등 별도 속성은 이번 수정 범위에 포함하지 않는다.

변환 단위 검사 5개 통과. 개발 서버의 실제 Chrome에서 2×2 표를 붙여 넣고 마우스로 첫 행 높이를 늘린 뒤 HWPX/HWP 저장·재저장·다시 열기를 검사했다. 저장 결과의 행 높이와 1:3 열 비율을 검증했다. 타입 검사 오류·경고 0. 한컴에서의 표시와 자동 행 높이·페이지 나눔의 완전한 일치는 아직 검증하지 않았다.

현재 구조는 Word용 TipTap과 한글용 rhwp를 함께 호스팅하며, Word→HWPX 변환은 별도 초기 구현이다. 이번 보완은 완전한 DOCX↔HWPX 호환성을 의미하지 않는다. 앞으로 원래 형식의 편집·저장과 다른 형식으로의 변환을 UI에서 구분하고, 표·이미지·목록·구역·스타일별 지원표와 왕복 검증 자료를 갖추어야 한다.

## 문서 형식 선택 화면

root의 영문 소개문과 자동 편집기 진입을 없애고 Word / 한글 선택 화면으로 교체했다. Word 선택은 `?editor=word`에서 편집기를 지연 로딩한다. 새 문서의 기본 저장은 DOCX이며 같은 탭의 기존 초안은 유지한다. 한글 선택은 `hwp.html?new=1`에서 rhwp의 새 HWPX 문서를 만들고, 저장 형식에서 HWP도 선택할 수 있다. 한글 화면의 형식 선택 링크는 미저장 변경을 확인한 뒤 시작 화면으로 돌아간다.

개발 서버와 production preview에서 형식 선택→한글 새 문서→선택 화면 복귀→Word 편집→기본 DOCX 저장→HWPX/HWP 내보내기·재열기 검사를 추가했다. 기존 Word smoke 검사도 통과했다. 1280×800 화면 이미지를 확인했으며 390px 화면의 가로 넘침이 없음을 측정했다. 선택 화면과 편집기 분리는 별도 통합 저장소로의 완전한 이관을 의미하지 않는다.

독립 검토에서 Word 지연 로딩 청크의 첫 방문 캐시 누락 가능성을 지적했다. 서비스 워커 등록·제어 확보를 Word 로딩보다 먼저 수행하도록 수정했고, 실제 preview 브라우저에서 첫 방문 직후 오프라인 새로고침으로 Word 편집기가 다시 열리는 것을 검증했다. 이 검사는 한글 편집기의 오프라인 사용을 보장하지 않는다.
