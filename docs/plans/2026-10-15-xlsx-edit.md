## 1. 목표와 완료의 정의

사용자가 `/xlsx`에서 셀·수식·서식을 고치고, 다음 두 가지로 저장할 수 있다.
- **다른 이름으로 저장**: 새 파일. 원본은 그대로 둔다.
- **원본에 저장**: 열었던 파일에 덮어쓴다. 아래 보존 조건을 통과할 때만 허용한다.

저장 동작은 Word·PDF의 계약을 따른다.
- 취소·권한 거절·쓰기 실패가 나면 파일 연결·dirty·실행 취소를 그대로 둔다.
- 다른 이름으로 저장에 성공하면 다음 저장은 새 파일로 간다.
- 외부에서 바뀐 파일에는 쓰지 않는다.
- 저장 중에 새로 편집한 내용은 계속 dirty로 남는다.

범위 밖(이 계획에서 하지 않음):
- `.xlsx` 밖의 형식(xlsm·xls·ods·csv 저장)
- 공동 편집, 오프라인 Excel(서비스 워커는 엔진을 캐시하지 않는다 — 그대로)
- push·배포
- B2 이후의 화면 오류(사용자가 하나씩 알려 준다)

## 3. 설계

### 3.1 역할 나누기

- **셸**(`XlsxViewer.svelte` → `XlsxEditor`로 바꾼다): 다음을 가진다.
  - 파일 핸들, 열 때의 원본 바이트·해시, epoch
  - 저장 흐름 전부: 선택기, 검사, 잠금, OPFS 사본, 쓰기
  - dirty 표시(셸 이탈 확인과 엔진 전환에 쓴다)
- **엔진**: 편집과 실행 취소, 요청받은 revision의 xlsx 바이트 만들기, 저장 ACK를 받으면 `saved` 갱신.
  - 엔진은 파일을 쓰지 않는다.
  - 엔진 안의 열기·저장·다른 이름 저장·자동 저장·끌어놓기·인쇄는 모두 **셸에 요청하는 메시지**로 바꾼다(B1 해결).
  - 엔진이 직접 선택기를 열게 되돌리지 않는다. 그러면 저장 계약을 우회한다.

### 3.2 브리지 프로토콜 2 (`sketch-xlsx:*`, protocol 2)

| 방향 | 메시지 | 내용 |
|---|---|---|
| 엔진 → 셸 | `state` | `{ dirty, revision }`. 바뀔 때마다. `revision`은 문서 workbook `Arc`가 바뀔 때마다 1 증가 |
| 엔진 → 셸 | `request` | `{ action: 'open' \| 'save' \| 'saveAs' \| 'print' }`. 엔진 메뉴·단축키(Ctrl+S·Ctrl+Shift+S·F12·Ctrl+O)·끌어놓은 파일(`{ action: 'open', name, bytes }`) |
| 셸 → 엔진 | `snapshot` | `{ requestId, epoch }` → 엔진이 지금 `Arc<Workbook>`을 `requestId`로 보관하고 `file.saveBytes`(xlsx)를 실행 |
| 엔진 → 셸 | `snapshot` | `{ requestId, epoch, revision, bytes }` 또는 `{ ok:false, error }`. 텍스트 상자 초안은 먼저 커밋을 시도하고, 실패하면 거절 |
| 셸 → 엔진 | `saved` | `{ requestId, epoch, name }`. **디스크 `close()` 성공 뒤에만** 보낸다. 엔진은 보관한 `Arc`를 `doc.saved`에 넣는다. 그 뒤 편집이 없으면 clean, 있으면 dirty가 남는다 |
| 셸 → 엔진 | `discard` | `{ requestId }`. 실패·취소한 스냅샷을 놓는다 |
| 기존 | `open`·`opened`·`ready`·`failed` | 그대로. `opened`에 열기 경고·`encrypted`·`vba` 여부를 더한다 |

- 늦은 메시지 규칙은 지금과 같다: origin·source·protocol·requestId·epoch를 검사한다.
- ACK가 오지 않으면 엔진은 dirty를 유지한다. 저장 완료로 치지 않는다.

### 3.3 편집 모드에서 보기 전용 두 층을 바꾸는 법

- ① 명령 게이트를 끄지 않고 **바꾼다**.
  - `view_only`를 `mode: View | Edit`로 바꾼다.
  - Edit에서도 거절하는 목록을 둔다: 엔진이 직접 파일을 여닫는 명령(`file.open`(브리지 허가 외)·`file.new`·`file.close`·`file.save*`·`file.export*`·`file.saveBytes`(브리지 외)), 외부 연결 새로 고침 등.
  - 이 목록은 시험으로 고정한다.
- ② 매 프레임 되돌림(`guard`)은 Edit에서 끈다. 대신 문서가 하나인지 지킨다(셸이 한 파일만 가진다).
- `services.download`·`print`·`open_async`·`inbox`는 브리지 `request`로 연결한다. `grid.autosave`는 항상 꺼 두고, 토글은 숨기거나 누르면 거절한다(결정 Q5).
- 보기 모드는 남긴다: 암호를 풀어 연 파일 등 저장할 수 없는 문서, 엔진 시작 실패 뒤 등.

### 3.4 저장 흐름 (셸, PDF `createSaver`와 같은 모양)

1. 스냅샷을 요청한다(엔진 → 바이트 + revision).
2. **선택기 전에** 검사를 모두 끝낸다:
   - ZIP·`.xlsx` 구조
   - 보호 상태(암호·매크로·디지털 서명 part 있음 → 원본 저장 거절)
   - 원본에 저장이면 보존 검사(3.5)
3. 대상을 정한다.
   - 원본에 저장: 열 때의 핸들.
   - 다른 이름으로 저장: `showSaveFilePicker`. 선택기는 고른 파일을 비우므로, 그 뒤에는 거절할 일이 없게 한다.
4. Web Lock(`sketch-docs-xlsx-save`) 안에서:
   - 대상 해시를 다시 확인한다. 외부에서 바뀌었으면 거절하고 "다른 이름으로 저장"을 안내한다.
   - 원본 덮어쓰기면 첫 번에 OPFS 사본을 남긴다(다시 읽어 해시 확인. 실패하면 쓰지 않는다).
   - 그 뒤 `writeIfUnchanged`로 쓴다.
5. 성공하면 엔진에 `saved`를 보내고, 셸 기준(바이트·해시·핸들·이름)을 갱신한다.
6. 실패·취소하면 `discard`를 보낸다. dirty·undo·연결은 그대로다.
7. 같은 탭의 저장은 직렬로 처리한다. 결과는 같은 epoch에만 반영한다.

OPFS 사본 저장소는 PDF와 폴더를 나누어 서로 밀어내지 않게 한다: `sketch-docs-xlsx-recovery`, 같은 5개 규칙. 공통 코드는 `src/pdf/recovery.ts`에서 폴더 이름만 인자로 받게 일반화한다. PDF 시험이 그대로 통과해야 한다.

### 3.5 보존 검사 (원본에 저장할 때만)

목표: "편집한 것 말고는 빠진 것이 없을 때만" 덮어쓴다.

1. **열 때 한 번** 편집하지 않은 상태의 스냅샷을 받아 원본과 비교한다. 이것이 그 파일의 "왕복 손실"이다.
   - 비교기 `src/xlsx/compare.ts`(fflate로 ZIP 풀기)가 보는 것: part 목록·content type·관계, 시트별 셀(값·수식·스타일)·병합·조건부 서식·데이터 유효성·메모·하이퍼링크·정의된 이름·그림·차트·표·피벗 개수.
   - 손실이 있으면 그 파일은 **원본 저장 불가**다(다른 이름으로 저장만). 화면에 무엇이 빠지는지 한국어로 보여 준다.
2. 저장 때는 원본과 편집본을 비교한다. 차이가 "편집한 셀·서식·시트"에만 있는지 본다.
   - 편집 범위는 엔진이 revision마다 바뀐 시트·범위 목록으로 알려 준다. 정확한 방식은 단계 0 측정 뒤 정한다.
   - 처음에는 1만 시행하고, 2는 "시트 수·part 집합·편집하지 않은 시트의 셀 해시가 같다"로 시작한다.
3. 비교기 자체를 변이 시험으로 확인한다: part를 하나 빼거나 셀 하나를 바꾼 사본을 반드시 거절해야 한다.

이 검사는 "우리가 재는 항목에서 손실 0"을 뜻할 뿐, 무손실을 증명하지 않는다. 첫 덮어쓰기 전 OPFS 사본이 마지막 안전망이다.

### 3.6 복구·잠금·이탈 (단계 3)

- **편집 중 복구 사본**:
  - dirty이고 30초 동안 입력이 없으면 스냅샷(엔진 xlsx 바이트)을 OPFS `sketch-docs-xlsx-drafts`에 파일당 1개 남긴다.
  - 다음에 `/xlsx`를 열면 "복구할 문서가 있습니다"라고 묻는다.
  - 이 사본은 엔진이 쓴 xlsx라 왕복 손실이 같다고 안내한다.
  - 저장에 성공하거나 사용자가 버리면 지운다.
- **탭 간 잠금**:
  - 저장은 Web Lock + 해시 재확인으로 막는다(위 4).
  - 같은 파일을 두 탭에서 편집하는 것은 BroadcastChannel로 "다른 탭에서 열려 있음"을 알린다(막지는 않는다 — 결정 Q8).
- **이탈 경고**: 셸 `EditorShell`의 dirty·이탈 확인에 Excel dirty를 연결한다(Word·PDF와 같은 경로).

### 3.7 한국어·크기

- 새 문구는 셸에 한국어로 둔다. 엔진 쪽 새 문구(거절 사유 등)는 `ko-sketch.json`에 더한다. `xlsx-i18n-audit`으로 남은 영어를 다시 잰다.
- WASM은 지금 24,231,303 B(23.11 MiB)이고 24 MiB 경고선까지 0.89 MiB 남았다. 편집 모드는 이미 들어 있는 엔진 코드를 켜는 것이라 큰 증가는 없을 것으로 **추정**한다. 단계마다 빌드 뒤 크기를 기록하고, 경고선을 넘으면 멈추고 보고한다.
- **"보기 전용" 배지·문구**는 모드 표시로 바꾼다.

각 단계는 독립 커밋이다. 브라우저 시험과 `npm run verify`를 돌리고, 저장·덮어쓰기 단계는 변이 시험을 한다. 무거운 실행(cargo·trunk·verify)은 조율자 허락 뒤에 한다.

## 6. 위험

- **비교기가 놓친 손실로 원본을 덮어쓴다** → 첫 덮어쓰기 전 OPFS 사본, 비교 항목을 문서에 적는다. 무손실이라고 주장하지 않는다.
- **편집 모드에서 엔진이 파일을 직접 다룬다**(다운로드 등) → 서비스를 모두 브리지 요청으로 바꾼다. 거절 목록을 시험으로 고정한다.
- **엔진 상태와 셸 dirty가 어긋난다** → revision과 ACK로 맞춘다. 셸은 엔진의 `state`만 믿는다.
- **WASM 경고선(24 MiB)** → 단계마다 잰다.
- **upstream 갱신 때 overlay 충돌** → `upstream:check`가 잡는다. 거절 목록은 명령 id 기준이라 새 명령이 생기면 시험이 알린다(명령 전수 시험).
