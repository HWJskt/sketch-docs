## 1. 목표와 완료의 정의

사용자가 `/xlsx`에서 셀·수식·서식을 고치고 다음 두 가지로 저장할 수 있다.
- **다른 이름으로 저장**: 새 파일. 원본은 그대로 둔다.
- **원본에 저장**: 열었던 파일에 덮어쓴다. §3.5 조건을 통과할 때만 허용한다.

저장 동작은 Word·PDF 계약을 따른다.
- 취소·권한 거절·쓰기 실패가 나면 파일 연결·dirty·실행 취소를 그대로 둔다.
- 다른 이름으로 저장에 성공하면 다음 저장은 새 파일로 간다.
- 외부에서 바뀐 파일에는 쓰지 않는다.
- 저장 중 새로 편집한 내용은 계속 dirty로 남는다.
- 입력 중인 셀 값도 저장에 들어간다.

범위 밖:
- `.xlsx` 밖 형식으로 저장·내보내기(CSV·HTML·PDF 파일)
- 데이터 가져오기(Get Data)
- 그림 삽입
- 암호 통합 문서
- 공동 편집, 오프라인 Excel
- push·배포
- B2 이후 화면 오류

## 3. 설계

### 3.1 역할

- **셸**(`XlsxViewer.svelte` → `XlsxEditor.svelte`):
  - 파일 핸들, 열 때 원본 바이트·해시, epoch를 가진다.
  - 저장 흐름 전부를 가진다: 선택기, 권한, 검사, 잠금, OPFS 사본, 쓰기.
  - dirty·busy를 `EditorShell`에 보고한다.
- **엔진**: 편집·실행 취소, 요청받은 스냅샷의 xlsx 바이트 만들기, ACK를 받으면 `saved` 갱신.
  - 파일·다운로드·인쇄 창·외부 URL을 직접 다루지 않는다.
  - 열기·저장 같은 사용자 동작은 셸에 `request`로 보낸다(B1).

### 3.2 명령·UI 경로 처리표 (편집 모드)

가로채는 자리는 `SheetApp::run_command`(`ui-egui/src/lib.rs:352`), `session.run`보다 앞이다.
- 명령 id로 판정한다(`Dialog` 요청이나 `download`로는 save·saveAs를 구별할 수 없다).
- UI 직접 경로는 그 함수 자리를 patch한다.

| 경로 | 처리 |
|---|---|
| `file.save` | → `request save` |
| `file.saveAs` | → `request saveAs` |
| `file.open`(매개변수 없음), 열기 대화상자 "찾아보기", Ctrl+O | → `request open`(B1). 셸이 dirty면 확인 → 셸 선택기 |
| `file.open`(브리지 허가 1회) | 허용(지금과 같다) |
| 끌어놓은 파일 | → `request open {name, bytes}`. 셸이 같은 검사(확장자·ZIP·크기·dirty 확인) 뒤 브리지로 연다 |

| `file.saveBytes`(UI·백스테이지 `export_as`에서) | 거절. 스냅샷은 브리지가 엔진 함수로 직접 만든다(§3.3) |
| `file.exportCsv`·`exportHtml`, `file.exportPdf`, 백스테이지 다른 이름으로 저장 페이지의 형식 목록·다운로드 단추 | 거절(Q6). 페이지의 xlsx 저장 단추는 `request saveAs` |

| 그리드 자동 필터(명령 밖 변경) | 허용(편집). dirty는 포인터로 잡힌다. revision 갱신은 §3.3 |

이 표는 시험으로 고정한다.
- **명령 전수 시험**: 엔진 명령 목록을 모두 실행해, 문서가 하나 그대로이고 `download`·`print`·`open_url` 호출이 "허용" 행 밖에서 0회인지 단언한다.
- **UI 경로 시험**: 리본·백스테이지 저장·다른 이름·열기, Ctrl+S, Ctrl+Shift+S, F12, Ctrl+O, Ctrl+P, 열기 대화상자 찾아보기, Get Data, 끌어놓기를 브라우저에서 하나씩 눌러 기대 메시지를 확인한다.

### 3.3 브리지 프로토콜 2 (`sketch-xlsx:*`, protocol 2)

| 방향 | 메시지 | 내용 |
|---|---|---|
| 엔진 → 셸 | `state` | `{ dirty, editing, revision, busy }`. `editing`은 셀·텍스트 상자 입력 중. 셸은 `dirty \|\| editing`을 이탈 경고에 쓴다 |
| 엔진 → 셸 | `request` | `{ action: 'open' \| 'save' \| 'saveAs' \| 'print', name?, bytes? }` |
| 셸 → 엔진 | `snapshot` | `{ requestId, epoch, docUid }` |
| 엔진 → 셸 | `snapshot` | `{ requestId, epoch, docUid, rev, bytes }` 또는 `{ ok:false, error }` |
| 셸 → 엔진 | `saved` | `{ requestId, epoch, docUid, name }`. **쓰기 `close()` 성공 뒤에만** 보낸다 |
| 셸 → 엔진 | `discard` | `{ requestId }` |
| 기존 | `open`·`opened`·`ready`·`failed` | `opened`에 `warnings`·`docUid`를 더한다 |

스냅샷 절차(엔진):
1. `commit_edit`(셀 입력)과 텍스트 상자 초안을 커밋한다. 실패하면 거절한다.
2. `store_view_state`를 부른다.
3. **그 뒤** 현재 `Arc<Workbook>`을 `held[requestId]`에 잡는다.
4. 잡은 `Arc`에서 `io::save_bytes(.., "x.xlsx")`로 원시 바이트를 만든다. base64·JSON을 거치지 않고 ArrayBuffer로 전송한다(100 MB 메모리).

ACK 절차(엔진, `docUid`·`epoch`가 맞을 때만):
- 지금 `wb`가 `held`와 같은 포인터면 `saved = wb`이고, 문서는 clean이 된다.
- 아니면 `saved = held`이고 dirty가 남는다.
- 저장 중 화면만 움직여도(스크롤·시트 전환) 포인터가 바뀌어 dirty가 남는다. **잘못된 dirty는 허용**한다(안전한 쪽). 잘못된 clean은 시험으로 0을 단언한다.

카운터 이름은 `sketch_rev`다(기존 `DocState.revision`과 섞지 않는다). `wb` 포인터가 바뀌면 증가한다.

셸의 시간 제한:
- 스냅샷 응답이 60초를 넘으면 실패로 처리하고 `discard`를 보낸다.
- 저장 중에는 `busy`를 보고해 엔진 전환을 막는다(`EditorShell.svelte:77`).

### 3.4 저장 흐름 (셸, PDF와 같은 모양)

1. **원본에 저장**: 클릭 직후, 긴 작업 전에 `requestPermission({mode:'readwrite'})`를 받는다. 거절이면 멈추고 "다른 이름으로 저장" 안내.
2. 스냅샷을 요청한다.
3. **선택기 전에** 검사를 모두 끝낸다:
   - ZIP 구조
   - 원본 저장이면 §3.5 판정
4. 대상을 정한다.
   - **원본에 저장**: 연 핸들.
   - **다른 이름으로 저장**: `showSaveFilePicker`. 클릭이 만료됐으면 PDF처럼 "한 번 더 누르기"를 띄운다.
   - 선택기로 **원본 자체를 고르면**(`isSameEntry`) 원본 덮어쓰기로 처리한다.
     - §3.5 판정이 "원본 저장 불가"인데 원본을 골랐다면: 선택기가 이미 파일을 비웠으므로 셸이 가진 원본 바이트를 **그대로 다시 쓰고**(OPFS 사본 먼저) 거절을 알린다.
     - 이 경로는 시험과 변이로 고정한다.
5. Web Lock 안에서:
   - 대상 해시를 다시 확인한다. 바뀌었으면 거절하고 안내한다.
   - 원본 덮어쓰기의 첫 번이면 OPFS 사본을 남긴다(다시 읽어 해시 확인. 실패하면 쓰지 않는다).
   - `writeIfUnchanged`로 쓴다.
6. 성공하면 `saved`(ACK)를 보내고 셸 기준(바이트·해시·핸들·이름)을 갱신한다.
7. 실패·취소하면 `discard`를 보낸다. dirty·undo·연결은 그대로다.
8. 탭 안 저장은 직렬로 처리한다. 결과는 같은 epoch·docUid에만 반영한다.

잠금 이름은 `sketch-docs-office-save`다.
- 앞으로 붙일 Office 엔진(docx·pptx)도 이 이름을 함께 쓴다(office-craft §5.2: 같은 파일을 다른 엔진에서 열 수 있다).
- PDF는 기존 `sketch-docs-pdf-save`를 유지한다(바꾸면 PDF 동작이 바뀐다).
- 탭 사이에서는 해시 재확인이 실제로 막는다.

OPFS 원본 사본은 폴더 `sketch-docs-xlsx-recovery`, 같은 5개 규칙이다.
- `src/pdf/recovery.ts`를 폴더 이름만 인자로 받게 일반화한다.
- PDF 시험이 그대로 통과해야 한다.

`showSaveFilePicker`가 없는 브라우저(Safari·Firefox):
- 저장 단추를 끄고 안내한다(PDF와 같다, Q12).
- `<input type=file>`로 연 파일은 핸들이 없어서 "저장"이 "다른 이름으로 저장"이 된다.

### 3.5 보존 검사 (원본에 저장할 때만)

"편집한 것 말고 빠진 것이 없다"를 **지금 전부 증명할 방법은 없다**. 그래서 원본 저장을 좁게 허용한다.

**판정 1 — 열 때 왕복.**
- 열자마자 편집 전 스냅샷을 받아 원본과 비교한다.
- 비교기 `src/xlsx/compare.ts`는 worker에서 fflate로 돈다(100 MB를 메인 스레드에서 풀지 않는다).
- 비교 방식:
  - part 이름이 아니라 **관계 그래프로 정규화**해서 맞춘다(part 이름은 새로 붙는다).
  - 객체별 **내용 해시**를 비교한다(그림·차트·표·피벗은 개수가 아니라 내용).
  - 스타일은 인덱스가 아니라 **해석된 서식**(글꼴·채우기·테두리·숫자 서식 코드)으로 비교한다.
  - 항목은 **단계 0이 잰 요소 목록 전체**다(행 높이·열 너비·숨김·틀 고정·시트 표시·탭 색·인쇄 설정·보호·셀 서식 있는 텍스트·테마·글꼴·스파크라인·`extLst`·docProps 포함).
  - 엔진이 늘 다시 만드는 것(calcChain 등)은 단계 0 측정으로 정한 "허용 차이" 목록에만 둔다.
- 열기 경고가 하나라도 있으면 무손실이 아니다.
- 손실이 있으면 원본 저장 불가다. 무엇이 빠지는지 한국어로 보여 준다.

**판정 2 — 편집 범위.**
- 엔진이 열린 뒤 실행한 undo 가능 명령 id 집합을 `state`로 알린다.
- 원본 저장은 **구조를 바꾸지 않은 편집**에서만 허용한다.
  - 행·열 삽입·삭제, 시트 추가·삭제·이름 바꾸기·이동, 정의된 이름 변경 등 "구조 명령 목록"이 하나라도 있으면 원본 저장 불가다.
  - 이유: passthrough 셀 참조가 고쳐지지 않고, 다른 시트 수식이 다시 써진다.
- "편집하지 않은 시트의 셀 해시" 비교는 **쓰지 않는다**. 재계산 값이 바뀌므로 정상 편집도 거절된다.
- 엔진 편집 추적 설계가 생기기 전에는 판정 2를 완료 조건에 넣지 않는다.

**비교기 시험**: part 삭제·관계 끊기·차트 내용 변경·스타일 해석값 변경·행 높이 변경 사본을 각각 거절해야 한다(변이).

이 검사는 "잰 항목에서 손실 0"을 뜻할 뿐이다. 첫 덮어쓰기 전 OPFS 사본이 마지막 안전망이다.

### 3.6 복구·잠금·이탈 (단계 3)

- **편집 중 복구 사본**:
  - OPFS `sketch-docs-xlsx-drafts`에 둔다.
  - 키 = 파일 이름 + 원본 해시 + 탭 id.
  - 메타데이터: 엔진 판(`CARGO_PKG_VERSION`·overlay 해시), docUid, epoch, `sketch_rev`, 시각.
  - 주기는 dirty이고 30초 무입력일 때. 큰 문서는 스냅샷 시간을 재서(단계 1a) 주기를 늘리거나 끈다.
  - 이것은 엔진이 쓴 xlsx라 **완전한 복구본이 아니다**(office-craft §5.2). 왕복 손실이 같다고 안내한다.
- **복구 제안**: Web Lock(`sketch-docs-xlsx-draft@<키>`)을 잡은 탭만 제안·삭제한다. 편집 중인 다른 탭의 사본은 건드리지 않는다.
- **같은 파일 두 탭**: BroadcastChannel로 "다른 탭에서 열려 있음"을 알린다(핸들을 보낼 수 있는지는 미확인 → 이름+해시로 판별). 저장 때 해시 재확인이 실제로 막는다.
- **이탈 경고**는 단계 1a로 옮겼다(§4).

### 3.7 한국어·크기

- 새 문구: 셸은 한국어로 쓴다. 엔진 쪽 새 문구는 `ko-sketch.json`에 더하고, `xlsx-i18n-audit`으로 다시 잰다.
- WASM 지금 24,231,303 B(23.11 MiB), 24 MiB 경고선까지 0.89 MiB.
  - 편집 모드는 있던 코드를 켜고 브리지가 조금 늘어날 것으로 **추정**한다.
  - 단계마다 크기를 기록하고, 경고선을 넘으면 멈추고 보고한다.
