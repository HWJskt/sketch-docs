## 2. Word browser data a migration must handle (Task 2)

### Where the data lives

- All engines share a single origin: `https://docs.sketchps.app`, plus `sketch-docs.pages.dev`, which is a **different origin with separate storage**.
- The Word engine runs in a **same-origin iframe** at `/engines/word/index.html`. localStorage, IndexedDB, OPFS, Web Locks and Cache Storage are scoped **per origin, not per path**. So the shell and every engine iframe (`/engines/word/`, `/rhwp/`, `/engines/gridcraft/`) see one shared namespace.
- A WordCraft engine served from the same origin could read `edentext-*` data directly. By the same token, any WordCraft key it writes must not collide with these keys.
- sessionStorage is per tab and per origin. It is shared between frames of the same tab.

### EdenText's per-document scoping

- Defined in `source/edentext/src/lib/storage/docScope.ts`.
- **`docKey(name)` returns `name` for the first document (empty id) and `name@<docId>` for the others** (`docScope.ts:111-114`).
- Up to 10 documents (`MAX_DOCS`, `:21`).
- If retention is `none`, `docStore` is in-memory (`:102`) and nothing per-document is persisted.
- `pruneOldDocuments` (`:163-169`) drops closed documents according to `edentext-keep-documents`, and always drops protected ones.

### Cache Storage

- **EdenText's own service worker is disabled** at build time: `build-engines.mjs:101` rewrites `main.ts` to `if (false && 'serviceWorker' in navigator)`. So `edentext-v3` (`source/edentext/public/sw.js:5`) is never created by Sketch Docs.
- The shell SW `public/sw.js:3` uses `sketch-docs-<build>`. Its scope is the site root, so it also caches `/engines/word/**` responses.
- On activate it deletes old `sketch-docs-*`, `edentext-shell-*` and `edentext-v\d+` caches (`:4,30`).

### BroadcastChannel / storage events

None in EdenText or the shell (grep found no `BroadcastChannel`, `addEventListener('storage'` or `onstorage`). Cross-tab coordination uses Web Locks and the `edentext-live@` markers.

### Other same-origin keys that WordCraft must not collide with

- Shell: `sketch-docs-last-engine` (localStorage, `src/engines.ts:5`).
- rhwp-studio (Hangul): `rhwp-settings`, `rhwp-local-fonts`, `rhwp-symbols-recent`, `rhwp:compareDebug`, all in `source/hop/third_party/rhwp/rhwp-studio/src`.
- svelte-pdf-mini has an IndexedDB store `svelte-pdf-mini/cache` (`dist/core/cache/kv.js:14`), but our code does not use it.
- GridCraft: none found.

### Migration notes

- **Data a user could lose silently on the switch:**
  - autosaved documents: `edentext-doc*` plus side-cars, `edentext-images`, `edentext-snapshots*` and `edentext-doc-broken`
  - the personal dictionary
  - AutoText and AutoCorrect lists
  - collected words
  - AI settings, including the API key, and AI chat
  - recent-file handles

  To export or import them, a new build must parse EdenText's TipTap JSON. §7.2 rules out shipping EdenText's AGPL serializer in the MIT build. So either offer a "download as .docx" export while the build is still AGPL, or write an independent reader of the JSON shape. The reader is a design risk to review.
- **`FileSystemFileHandle`s exist only in IDB `edentext-recent/handles`.** They are structured-cloneable, so WordCraft could reuse them without EdenText code, but permission must be requested again.
- **The `edentext-ai` key holds a plain-text API key.** Decide whether to migrate it or delete it, and say which to the user.
