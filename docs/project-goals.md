# Word와 한글 웹에디터 개발 목표

기준일: 2026-10-11

## 최종 목표

별도 프로그램 설치 없이 하나의 웹에디터에서 로컬 디스크의 Word·한글 문서를 열어 편집하고, 원본 파일에 저장하거나 다른 이름으로 저장하며, 새 문서를 DOCX·HWPX 파일로 작성·저장할 수 있는 문서 작성 환경을 만든다.

사용자가 실제 문서 업무를 웹앱에서 수행하고, 결과물을 Microsoft Word·한컴오피스 사용자에게 전달해 계속 편집할 수 있어야 한다. 단순 파일 뷰어, 다운로드 전용 변환기, 두 편집기를 한 화면에 배치한 상태만으로는 목표를 달성한 것으로 보지 않는다.

## 필수 로컬 파일 작업

| 작업 | 요구 동작 |
|---|---|
| 기존 문서 열기 | 로컬 디스크의 `.docx`, `.hwp`, `.hwpx`를 선택해 편집한다. |
| 저장 | 사용자가 열었던 파일의 위치와 형식을 유지하고 수정 내용을 해당 파일에 반영한다. |
| 다른 이름으로 저장 | 저장 위치·파일명·지원 형식을 선택해 별도 파일을 만든다. 별도 대상을 선택했다면 기존 파일은 유지한다. |
| 새 문서 작성 | 빈 문서에서 본문·표·이미지·서식을 작성한다. |
| 새 문서 최초 저장 | `.docx` 또는 `.hwpx`를 선택하고 로컬 디스크의 지정 위치에 저장한다. |
| 최초 저장 이후 | 일반 저장은 저장된 파일을 갱신한다. 다른 이름으로 저장이 성공하면 이후 일반 저장은 새 파일을 대상으로 한다. |

일반 저장은 브라우저 내부 자동 저장이나 매번 별도 파일을 다운로드하는 동작으로 대체하지 않는다. 사용자가 선택한 파일에 대한 쓰기 권한과 연결을 유지하고 해당 파일을 갱신해야 한다. 브라우저가 권한을 회수한 경우에는 다시 권한을 요청한다.

저장 취소·실패 시 기존 파일 연결과 미저장 변경 상태를 유지한다. 다른 이름으로 저장에서 기존 파일을 선택했다면 덮어쓰기 의사를 확인한다. 저장 중 추가 편집된 내용은 미저장 상태로 남긴다. 파일이 외부 프로그램에서 바뀐 경우 조용히 덮어쓰지 않고 충돌을 처리한다.

## 문서 형식과 편집 범위

- DOCX·HWP·HWPX 문서를 열고 편집하며 각각의 형식으로 저장한다. 기존 HWP 문서의 저장을 HWPX 변환만으로 대체하지 않는다.
- 새 문서는 최소 DOCX와 HWPX 두 형식으로 저장할 수 있어야 한다. 작성 시작 시 엔진을 선택하더라도 최종적으로 다른 형식으로 내보낼 수 있어야 한다.
- DOCX와 HWP/HWPX 사이의 형식 변환을 제공한다. 지원 요소는 내용·서식을 유지하고 미지원 요소와 예상 손실을 저장 전에 표시한다.
- 본문, 문자·문단 서식, 목록, 표와 병합 셀, 이미지, 글상자, 수식, 머리말·꼬리말, 구역과 페이지 설정을 최종 지원 범위에 포함한다.
- 열기·저장, 실행 취소·다시 실행, 찾기·바꾸기, 서식과 표·이미지 편집을 일관된 UI로 제공한다. 내부 엔진은 앱이 관리하고 사용자가 설치하거나 설정할 필요가 없어야 한다.
- 수정하지 않은 내용과 서식을 보존하고 원본 배치를 가능한 한 유지한다. 보존할 수 없는 요소가 있으면 원본을 보호하고 별도 저장 또는 작업 취소를 안내한다.
- edentext의 기존 ODT 기능은 유지한다.

구형 Word `.doc`, HWP 3 계열 및 모든 제품 버전의 완전한 동작 재현은 현재의 필수 완료 범위에 포함하지 않는다. HWP 기본 대상은 HWP 5 계열이다. 암호화·서명 등 특수 문서의 지원 범위는 별도 호환성 표로 확정하며, 미지원 상태를 일반 문서로 오인해 저장하지 않는다.

## 웹앱과 데이터 처리

기본 생성·열기·편집·저장은 브라우저에서 수행한다. 데스크톱 앱, 로컬 Python, 설치된 한컴오피스 또는 문서 변환 서버가 필수 의존성이 되어서는 안 된다. 일반 문서 작업에 원문을 외부 서버로 업로드할 필요가 없어야 한다.

로컬 원본 갱신과 저장 위치 선택을 지원하는 브라우저에서 전체 흐름을 충족해야 한다. 지원하지 않는 브라우저의 다운로드 방식은 제한 지원으로 표시하며 동일한 기능으로 설명하지 않는다. 구체적인 브라우저·운영체제 조합은 구현 검증을 거쳐 지원표에 기록한다.

자동 저장과 복구, 여러 문서 작업, 미저장 상태 안내를 제공한다. 브라우저 내부 복구본과 사용자가 지정한 로컬 파일은 구분하고, 복구본 저장을 로컬 파일 저장 완료로 표시하지 않는다.

## 선택적 AI 작성과 수정

모든 지원 형식에 AI 초안 작성과 본문·표·서식 수정 기능을 연결한다. 사용자가 변경 내용을 검토하고 취소할 수 있어야 한다. AI를 사용하지 않아도 편집기는 독립적으로 동작하며, AI를 활성화한 경우에만 선택한 공급자에게 필요한 문서 내용을 전송한다.

## 최종 완료 판단

대표 업무 문서군과 기능별 호환성 표를 기준으로 다음 항목을 검증한다. 실증 단계의 제한된 문서 지원은 최종 목표의 축소를 의미하지 않는다.

1. 로컬 DOCX·HWP·HWPX를 열어 본문과 표를 수정한 뒤 원본에 저장하고 재열면 변경이 유지된다.
2. 다른 위치·이름으로 저장한 파일에 변경이 유지되고 기존 원본은 변경되지 않는다. 이후 저장은 새 파일을 갱신한다.
3. 새 문서를 DOCX와 HWPX로 각각 로컬에 저장하고 Word·한컴오피스에서 정상적으로 열고 수정·재저장할 수 있다.
4. 지원하는 형식 간 변환에서 텍스트·표 구조·이미지·서식이 보존되고 손실 가능 항목이 명시된다.
5. 저장 취소·실패·권한 거부·외부 파일 변경·저장 중 추가 편집 상황에서 작업 내용이 조용히 사라지거나 저장 완료로 잘못 표시되지 않는다.
6. 새로고침·비정상 종료 이후 복구와 문서 전환에서 문서별 내용·파일 연결·편집 상태가 섞이지 않는다.
7. 한글 입력기의 조합 입력, 표 안 입력, 실행 취소와 단축키가 지원 브라우저에서 동작한다.
8. 기본 문서 작업이 문서 업로드나 별도 프로그램 설치 없이 동작한다.
9. 앱 자체 재열기 검사와 Word·한컴오피스 호환성 검사, 실제 렌더링 비교를 각각 수행한다. 자체 왕복 검사만으로 호환성을 판정하지 않는다.
10. AI 작성·수정은 사용자가 활성화한 경우에 동작하며 변경 검토·취소와 문서 버전 충돌 처리를 제공한다.

정량적인 페이지·배치 허용 오차, 대용량 한도, 응답 시간 기준은 대표 문서군을 확보한 뒤 구현 사양에서 확정한다. 모든 문서를 무조건 완벽하게 재현한다는 보장은 하지 않는다.

## 구현 수단과 목표의 관계

edentext·rhwp·HOP·hwpx-skill은 구현 후보와 참고 자원이다. 특정 라이브러리 채택 자체는 완료 기준이 아니다. [기술 스택 제안](architecture/web-editor-stack.md)은 구현을 위한 권장안이며 이 문서의 최종 목표와 구분한다.

작업 순서·모듈 책임·저장 및 복구 계약·검증 단계는 [구현 계획](implementation-roadmap.md)에 기록한다.
