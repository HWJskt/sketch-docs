## push·배포 — 단계 (2026-10-15 모두 끝남, 결과는 아래)

1. **보존 fork 만들기(결정 A, 사용자 승인 받고)**: `npm run mirrors:pin`이 `HWJskt/gridcraft`·`HWJskt/craft-libs`를 공개 fork로 만들고 고정 커밋에 `sketch-docs/pin-<commit>` 태그를 단다. `npm run mirrors:check`가 다섯 upstream 모두 "pinned"여야 한다.
2. **마지막 커밋에서 `npm run verify`**(깨끗한 트리). verify가 브라우저 러너 4개를 en-US로 한 번 더 돈다(리뷰 M2 조율자 결정).
3. **`git push origin main`**: 게이트가 `push gate: <sha> → refs/heads/main: verified (artifacts/verified.json)`를 찍고 통과해야 한다. 보고가 맞지 않으면 임시 worktree에서 다시 검사(10~20분). `--no-verify`는 쓰지 않는다.
4. **GitHub `verify`**: `gh run list --workflow verify --limit 3` — 가벼운 검사(`npm run check`·`npm run test:contracts`)가 성공해야 한다.
5. **`npm run deploy`**: verify 보고·커밋·dist 해시·깨끗한 트리·push된 커밋·mirror 태그를 확인한 뒤에만 올린다(첫 배포는 `Unknown internal error`로 한 번 실패한 적이 있다 — 같은 명령을 한 번 다시).
6. **`npm run test:live`**(배포 URL, 새 `/xlsx` 경로 포함) — 실패하면 배포 URL(`<hash>.sketch-docs.pages.dev`)로도 본다.
